Compilación y Despliegue

1. Firma Digital de la App y APK Release

Para empaquetar la versión final de producción, configuramos una llave de firma privada (release.jks) directamente en Gradle: 

signingConfigs {
    create("release") {
        storeFile = file("release.jks")
        storePassword = "123456"
        keyAlias = "my-key-alias"
        keyPassword = "123456"
    }
}
buildTypes {
    release {
        signingConfig = signingConfigs.getByName("release")
    }
}
📦 Genera el ejecutable firmado en app/build/outputs/apk/release/app-release.apk.

2. Microservicio Propios & API Externa (Retrofit)

Integramos ambos requerimientos consumiendo tanto nuestro microservicio en Spring Boot como una API pública externa:

🔌 Microservicio Propio (Spring Boot)

interface CimApiService {
    @GET("proyectos")
    suspend fun getProyectos(): List<CimRemoteDto>
}
// Base URL: http://10.0.2.2:8080/api/cim/

🌐 API Externa (JSONPlaceholder)

interface ExternalApiService {
    @GET("posts")
    suspend fun getExternalPosts(): List<CimRemoteDto>
}
// Base URL: https://jsonplaceholder.typicode.com/
Seguridad y Accesos

3. Control de Acceso por Roles (RBAC)

Sistema de autenticación y privilegios diferenciados almacenados en base de datos local:

🛡️ Rol Administrador (ADMIN)

Control total: sincroniza la API y microservicio, crea, edita y elimina registros, y administra cuentas de usuario.

👤 Rol Usuario Común (USER)

Perfil de consulta: busca en tiempo real, filtra por categorías (Chips), visualiza detalles técnicos y comparte contenido.

Capa de Datos

4. Persistencia Local con Room Database

Arquitectura Offline-First utilizando SQLite a través de Room para almacenar iniciativas y perfiles: 

@Entity(tableName = "cim_contents")
data class CimEntity(
    @PrimaryKey val id: String,
    val type: String,
    val title: String,
    val shortDescription: String,
    val areaTematica: String
)
💾 Los datos se exponen de forma reactiva mediante Flow hacia el ViewModel.
